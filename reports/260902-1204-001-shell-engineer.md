## What changed and why

Added `bootstrap.sh`, a one-command macOS onboarding script for a fresh clone, built with TDD
against fixture-isolated HOME/PATH throughout (no test ever touches the real machine).

- `bootstrap.sh`: requires Darwin (fails clearly otherwise); requires `brew` (prints the official
  install command/URL and stops without executing it if missing); installs `git`/`jq` with Homebrew
  only when missing, never upgrading; installs `herdr`
  (`curl -fsSL https://herdr.dev/install.sh | sh`) and Claude Code
  (`curl -fsSL https://claude.ai/install.sh | bash -s stable`) only when missing; links
  `~/.local/bin/jarvis` to this clone's absolute `bin/jarvis` and adds `~/.local/bin` to `PATH` via
  `~/.zprofile` (deduplicated); repairs a stale symlink silently but asks before replacing an
  unexpected file, refusing without any mutation when not running under a terminal; runs all
  dependency installs before the symlink publish step so a failed install can never leave a broken
  `jarvis` command; verifies every tool, the symlink target, PATH, and a read-only
  `bin/jarvis status`; and prints exactly two next actions (`Authenticate: claude`,
  `Start Jarvis: jarvis claude`). All paths are quoted throughout, including clone paths containing
  spaces.
- `bin/jarvis`: fixed root-directory resolution to follow symlinks (a loop, matching the standard
  idiom) instead of a plain `dirname "${BASH_SOURCE[0]}"`. **Found during implementation, confirmed
  with the user before proceeding** (out of this card's original `Owns:`): bash does not resolve
  symlinks in `BASH_SOURCE`, so the literal `~/.local/bin/jarvis` symlink this task creates would,
  once invoked via `PATH`, compute the wrong root and fail to source `scripts/` — this is why the
  pre-existing `bin/jarvis install-alias` command uses a shell alias with a baked-in path instead of
  a symlink. The user chose "fix `bin/jarvis`" over the other two options offered (stop and report;
  or ship the literal symlink and accept the breakage). This is the only change to `bin/jarvis`;
  `tests/jarvis-cli.test.sh` (unchanged, still green) plus this task's own symlink-invocation
  coverage in `tests/bootstrap.test.sh`/`tests/bootstrap-interactive.test.sh` (which run
  `bin/jarvis status` **through** the installed symlink, not the raw path) are what caught it and
  what now guard it. Recorded on the card under "Discovered during implementation".
- `tests/bootstrap.test.sh`: fresh install, fully installed rerun (brew/curl log empty — never
  invoked), missing Homebrew, non-macOS, dependency install failure (staging proof: neither the
  symlink nor `~/.zprofile` exist afterward), path with spaces (clone lives under `"My Clone"`),
  profile deduplication (two consecutive runs, one export line, unrelated content preserved),
  expected symlink repair (stale target, no prompt, non-interactive), unexpected destination
  refusal (regular file, non-interactive, byte-for-byte unchanged after refusal). Each case gets its
  own fully isolated fixture: its own `HOME`, its own curated bin dir standing in for `PATH` (real
  host git/jq/herdr/claude/brew/curl/uname are never reachable — only what a case stages), and its
  own copy of the clone.
- `tests/bootstrap-interactive.test.sh`: the one path that needs a real terminal
  (`[ -t 0 ]`/`[ -t 1 ]` can't be faked with a pipe) — drives `bootstrap.sh` under an actual
  pseudo-terminal via Python's `pty` module (already a project dependency; see
  `scripts/agent-spend.sh`/`scripts/context-size.sh`) and feeds the reply through it. Covers both
  accepting and declining the replacement of an unexpected destination.
- `README.md`: rewrote Initial-setup step 1 to describe `bootstrap.sh` end-to-end with the exact
  installer commands and URLs; the Herdr-runtime section now points at `bootstrap.sh` as the normal
  path and reframes `bin/jarvis install-alias` as the older manual alternative.
- `docs/herdr-runtime.md`: added a `## bootstrap.sh` section (behavior, staging, verification) and
  the command to the command list; documented the symlink-resolution fix and why it was needed.

## What I rejected, and why

- Did not make `bootstrap.sh` verify by invoking `bin/jarvis status` at its raw clone path. The
  brief's checklist separately names "the symlink target" and "read-only `bin/jarvis status`" as
  distinct verification items; invoking `status` through the installed `~/.local/bin/jarvis` symlink
  instead proves the actual thing a user will run works end-to-end, and is exactly what caught the
  root-resolution bug above during design — verifying the raw path would have hidden it.
- Did not add a shared `tests/` helper library for the two bootstrap test files. No other file in
  `tests/` sources a shared fixture library; each is self-contained. The ~30-line fixture-builder is
  duplicated between the two files rather than introducing a new convention outside this card's
  `Owns:`.
- Did not use `readlink -f` for symlink resolution in `bin/jarvis`/`bootstrap.sh` even though it
  works on this machine's BSD `readlink`. The manual loop is the older, more portable idiom (works
  on any bash 3.2+/BSD `readlink` without `-f` support) and needed no new external dependency.
- Did not touch `bin/jarvis install-alias` itself. It remains a valid, working alternative path; the
  README now explains the relationship instead of removing or changing it.
