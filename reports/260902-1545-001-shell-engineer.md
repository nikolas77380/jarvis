# 260902-1545-001 — shell-engineer report

## What was implemented

1. **MCP consent inheritance** (`scripts/agent-engine-lib.sh`: `claude_inherit_mcp_config`). Claude
   MCP consent (`mcpServers`, `enabledMcpjsonServers`) is recorded per project entry in
   `~/.claude.json`, keyed by absolute cwd. A freshly `git worktree add`-ed task worktree is a new,
   unconsented entry, so an MCP server the orchestrator already has working access to (e.g. Figma)
   looked unauthenticated inside the child even though the child inherits the real HOME/keychain.
   `claude_inherit_mcp_config(worktree, project_root)` copies just those two keys from the parent
   project's entry into the child's, merged with `+` so every other key on either side (e.g.
   `hasTrustDialogAccepted`) is preserved untouched. It never echoes, logs, or returns any value —
   its only observable effect is the rewritten JSON file. Wired into `engine_start` (now takes a 7th
   `project_root` arg) for the `claude` engine only, called on every spawn/review-handoff/switch so
   authorization stays fresh across the task's whole life, not just at first spawn.

2. **Capability preflight** (`agent-engine-lib.sh`: `role_capabilities`, `capability_preflight_prompt`,
   `capability_preflight_verdict`, `capability_preflight_pass`). A role declares required live
   capabilities as a plain frontmatter field — `capabilities: figma` (comma-separated for more than
   one) — never a name-to-capability map hard-coded in the runtime. `capability_preflight_pass` is a
   no-op (returns 0 immediately, no Herdr calls at all) when the role declares nothing. When it does,
   it sends a deterministic probe prompt to the freshly started session, waits for it to settle, reads
   the recent pane output, and requires the exact literal `CAPABILITY_PREFLIGHT_RESULT PASS` as the
   trailing non-blank line — anything else (a `FAIL` marker, silence, a timeout, stray output) is
   fail-closed by construction (`capability_preflight_verdict`'s only success branch).

   `scripts/agent-spawn.sh`, `scripts/agent-review.sh`, and `scripts/agent-switch.sh` each call this
   right after `engine_start` and before their substantive prompt (`BRIEF` / handoff note). On
   failure: the newly opened tab is closed, and the caller `die`s *before* writing/mutating task
   metadata — so a failed spawn leaves no meta file (worktree preserved for reconciliation, matching
   the existing failure convention), and a failed review-handoff/switch leaves the OLD agent/meta
   fully bound, untouched. In every failure path the substantive brief is provably never sent (asserted
   directly against the fake-Herdr call log in tests, not inferred).

3. **RULES.md / agents/orchestrator.md**: added the general invariant — the lead never fetches or
   absorbs external-source evidence on a specialist's behalf; that's what the capability-declaring
   role + preflight above exist to make routine instead of ad hoc.

4. **agents/design-qa.md**: declares `capabilities: figma` in frontmatter; added a rule that prefetched
   or unverified design-tool evidence can never back a `MATCH`/`APPROVE` — only its own live MCP calls
   can.

## Root cause (confirmed, not re-derived)

Already established before this task's implementation brief: Claude children inherit the real HOME
and keychain, but MCP consent is project-scoped by absolute cwd in `~/.claude.json`; the worktree-init
path created trust state (`hasTrustDialogAccepted`) for the new path but never copied `mcpServers`/
`enabledMcpjsonServers` from the parent. This PR is the fix plus the regression-guarding preflight the
user asked to keep on top of it.

## Open items / decisions for the reviewer

- The probe timeout (`CAPABILITY_PREFLIGHT_TIMEOUT_MS`, default 180000ms) and the marker-parsing
  heuristic (last non-blank line of recent pane output) are best-effort in the same spirit as this
  codebase's existing `quota_message_matches` pane-text heuristics — not provably immune to an edge
  case where the agent's own tool output happens to end with a line matching the marker text. No
  stronger structured-output channel exists in the current Herdr/engine_prompt surface; flagging this
  as a known limitation rather than a hidden one.
- Chose to re-run MCP-config sync on every `engine_start` (spawn, review-handoff, switch), not just
  first spawn, so a task's authorization stays fresh if the parent's own consent changes mid-task.
  This is idempotent and cheap; flag if a narrower "spawn-only" scope was intended instead.
