## Finding

### [P1] A delivered claim permanently prevents the next same-task handoff watcher

`scripts/codex-completion-watch.sh:131-145` treats any existing task-level metadata file as a
duplicate, without comparing the captured source generation, role, agent, or recipient identity.
After a successful delivery, `scripts/codex-completion-watch.sh:277-278` also refuses to supersede
that metadata. The resulting terminal state conflicts with `agents/orchestrator.md:107-114`, which
requires a fresh watcher after every spawn or switch, and with the task invariant of one claim per
task generation and recipient identity rather than one claim per task lifetime.

Reproduction from the implemented state machine:

1. Start a watcher for generation 1; it reaches `delivered` and leaves
   `codex-completion/<task-id>.meta` in place.
2. Hand the same task from engineer to reviewer with `agent-review.sh`; the canonical metadata now
   names generation 2 and the reviewer role/agent.
3. Run `codex-completion-watch.sh start` for generation 2. Registration exits with `completion
   watcher already registered` at line 133 before the new source binding is considered.
4. `reconcile --supersede` cannot clear the old claim because line 278 rejects `delivered`.

The focused test currently codifies only same-generation rejection at
`tests/codex-completion.test.sh:133-137`; it never performs the required
engineer → reviewer → fixer sequence. Preserve duplicate suppression for the same claim, but permit
an atomic new claim when the canonical source has advanced to a different legitimate generation
(and bind/archive records so generation and recipient identity remain explicit). Add a test that
delivers exactly once for each of the engineer, reviewer, and fixer generations while continuing to
reject a second registration for each individual claim.
