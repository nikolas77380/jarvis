## Implementation

Added an opt-in, plain-Bash completion watcher without changing the runtime's global Herdr session
default or the existing Claude/background-wait workflow.

- `scripts/codex-completion-watch.sh` provides `start`, `status`, and `reconcile`. Registration
  requires an explicit Herdr session and pane, captures the recipient Codex `agent_session.value`,
  captures the source task generation and canonical paths, then delegates the actual task/quota wait
  to the unchanged `agent-wait.sh`.
- Delivery re-reads the source metadata and card, verifies the exact generation/agent/engine/role,
  waits outside the model while a recipient is working, refuses a blocked recipient, and revalidates
  the Codex pane and agent-session identity immediately before sending one fixed completion prompt.
  No specialist terminal output is forwarded.
- `scripts/codex-completion-lib.sh` owns the watcher metadata schema and atomic state writes under
  `.harness-state/codex-completion/`. It reuses the shared task lock and linked-worktree mutation
  guard. Locks are released before `agent-wait.sh` or any Herdr call, so quota relaunch and network
  waits never occur under the shared task lock.
- States are `pending`, `waiting`, `delivering`, `delivered`, `failed`, and `uncertain`. Herdr prompt
  failure after delivery begins is deliberately `uncertain`, never `delivered`, and is never retried
  automatically. Reconciliation supports explicit retry, operator acknowledgement as delivered, or
  archival supersession before a fresh generation/recipient registration.
- Quota relaunches remain valid only when the existing `agent-history` JSONL contains a continuous
  same-engine switch chain whose notes begin `Provider quota reset.`. An unledgered task switch fails
  closed without delivery.
- `tests/codex-completion.test.sh` covers normal exactly-once delivery, duplicate registration,
  default and named sessions, legacy and timestamp task ids, nested and root project cards, recipient
  replacement, wrong recipient engine, blocked and busy recipients, explicit retry, stale task
  generation and supersession, missing task state, source-wait failure, quota relaunch, ambiguous
  delivery, and linked-worktree refusal.
- `agents/orchestrator.md` now contains the requested Codex-only registration paragraph.
  `docs/codex-completion.md` documents the state machine, recovery choices, and a real tracked-tab
  Herdr smoke-test procedure.
- Imported only this task's card from `/private/tmp/jarvis-codex-wake-plan` and its INDEX row. The row
  was advanced to the actual `in-progress` / `shell-engineer` state rather than retaining the staged
  checkout's stale `open` / `lead` values.

## Review round 1 fix

The reviewer found that the durable delivered record was keyed for the entire task lifetime, so a
later engineer/reviewer/fixer generation could not register its required watcher. The fix keeps the
single active claim but, under the existing task lock, allows `start` to archive an intact delivered
record only when canonical task metadata has a strictly newer generation. Same-generation duplicate
starts, generation rollback, and replacement of any non-delivered record remain failure-closed.

The regression was added first. `bash tests/codex-completion.test.sh` exited 1 at the original guard
with `completion watcher already registered for T1H`; after implementation it passes. The test drives
engineer generation 1, reviewer generation 2, and fixer generation 3, verifies exactly one prompt and
duplicate rejection per generation, checks rollback and unresolved/uncertain rejection, and reads the
archived records to verify their original source role, source agent, delivered status, and recipient
session identity.
