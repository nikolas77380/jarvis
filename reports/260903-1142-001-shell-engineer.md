# 260903-1142-001 — fix round 1 report

## Round 1 findings addressed

Reviewer round 1 (`reports/260903-1142-001-reviewer.md`, verdict REQUEST_CHANGES at `96b3054`)
found two blockers, one medium, and several low-severity issues. Summary and fixes are recorded
in the plan card under "## Review round 1"; this report gives the mechanical detail.

1. **Blocker — orchestrator rule bricks engineer -> reviewer handoff.** `agent-cleanup.sh` marks
   the task `stopped=1`; `agent-review.sh`/`agent-switch.sh` refuse outright on that. The rule in
   `agents/orchestrator.md` told the lead to run cleanup right after every acknowledged
   `agent-done`, including an engineer's, immediately before the very handoff that would fail.
   Fixed by rewording the rule (and `docs/herdr-runtime.md`): cleanup only ever runs for a
   generation the lead has decided will not go to another agent; `agent-review.sh`/`agent-switch.sh`
   already close the outgoing tab themselves as the last step of their own handoff, so there is
   nothing for cleanup to do there anyway.
2. **Blocker — event dedup key collides across generations at an unchanged HEAD.** The dedup key
   was `"$RUNTIME-$HEAD"`; a reviewer generation that commits nothing settles at the same HEAD as
   the engineer generation before it, so the second `agent-done` was silently dropped and that
   tab could never become eligible for cleanup. Fixed in `scripts/events-poll.sh`: the key is now
   `"$RUNTIME-$HEAD-g$DONE_GENERATION"` (falls back to the old form when no task `.meta` is
   resolvable). New regression: `tests/agent-cleanup.test.sh` scenario 4.
3. **Medium — docs overclaimed "automatic".** Nothing invokes `agent-cleanup.sh` unattended;
   reworded `docs/herdr-runtime.md` and `docs/inbox-and-decisions.md` to say so, and dropped the
   inaccurate "only auto-close path" claim (`agent-review.sh`/`agent-switch.sh` close tabs too).
4. **Low — unlocked identity reads.** Left alone; see "Left alone" in the plan card's round-1
   section for why (the state-lock helper is a single global slot, not stack-based — nesting a
   task lock inside the already-held `inbox` lock would silently drop the `inbox` lock's own
   mutual exclusion, a strictly worse race, for a benefit the generation/fingerprint match at
   close time already provides). Softened the comment instead of the unenforced claim.
5. **Low — PR test-count claim / stale base.** Not applicable to this report; fixed by merging.
6. **Merge hazard.** Merged `origin/main` (`f7634b8`) to pick up PR #5. Resolved 4 conflicts:
   `agents/orchestrator.md` (two independent, additive rules — kept both), `OVERVIEW.md` and
   `plan/INDEX.md` (unioned in PR #5's entries, which this branch's stale copies lacked),
   `plan/260902-1545-001-capability-aware-design-qa.md` (add/add conflict; this branch's own
   earlier commit already carried the fuller, verified-accurate "done, PR #5 merged" content that
   `origin/main`'s side lacked — kept this branch's version, diff-checked before choosing).

**Boundary (external, not fixable here):** a tab can be closed through channels this repo has no
visibility into (a human closing it directly, the terminal/Herdr server restarting) and there is no
Herdr event/hook this repo subscribes to for that. Discoverable only by trying to act on the tab and
observing the failure.

**Fixed (in scope, `Owns: scripts/herdr-runtime-lib.sh`):** `close_recorded_tab()` treated Herdr's
`tab_not_found` (tab already gone — not retryable, can never succeed) identically to a transient close
failure, dying forever and leaving `.meta` stuck at `stopped=0` with no path to reconciliation. Now
reconciles `tab_not_found` straight to the same `stopped=1` terminal state a real close reaches; any
other close failure still dies exactly as before. Commit `5c40782`. New test:
`tests/agent-cleanup.test.sh` scenario 5. Full suite, `shellcheck -S warning`, `plan-check.sh`,
`owns-check.sh` all clean.
