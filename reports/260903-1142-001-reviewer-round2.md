### F1. The repo's own vanished-agent detector is dead code, so the "external boundary" conclusion is half wrong

- `scripts/harness-observe.sh:45-50` (untouched by the diff)
- Claims affected, both in the delta: plan card `## Pre-round-2 addendum`, and
  `reports/260903-1142-001-shell-engineer.md` "Pre-round-2 addendum" -> "Left for the lead".

The real CLI, measured:

```
$ herdr --session harness agent get h_260902_1204_001_claude_1024562
{"error":{"code":"agent_not_found","message":"agent target h_... not found"},"id":"cli:agent:get"}
$ echo $?
1
```

`harness-observe.sh:45` runs that call as `OUT=$(... 2>/dev/null) || OUT=`, so a vanished agent
yields an empty `OUT`, which line 46-47 maps to `OBSERVED=unknown` and **emits no issue**. Line 50's
`issue runtime-agent-missing` is reachable only when Herdr exits **0** and returns a payload with an
empty `.result.agent` - which is not how Herdr reports a missing agent.

Concrete consequence: `scripts/agent-reconcile.sh:12` gates `--repair` on
`.issues|index("runtime-agent-missing")`. That string can never be present, so
`agent-reconcile.sh <task> --repair` cannot reconcile a task whose tab is gone. Measured now, on the
two tasks the engineer's own addendum cites:

```
$ bash scripts/harness-observe.sh 260902-1204-001 | jq -c '{observed:.runtime.observed,issues,consistent,nextAction}'
{"observed":"unknown","issues":[],"consistent":true,"nextAction":"continue"}
$ bash scripts/harness-observe.sh 260902-1545-001 | jq -c '{observed:.runtime.observed,issues,consistent,nextAction}'
{"observed":"unknown","issues":[],"consistent":true,"nextAction":"continue"}
```

Their recorded tabs `w2:t62` and `w2:t59` are absent from `herdr --session harness tab list`, which
returns 3 live tabs (`w2:t1`, `w2:t35` jarvis, `w2:t64` this reviewer). So the harness reports a task
whose agent provably no longer exists as `consistent: true` and tells the lead to `continue`.

Fleet-wide measurement, `.harness-state/*.meta`: 20 of 24 task metas record `stopped=0` with a tab
id, against 3 live tabs.

The boundary claim is right that the *disappearance* is external - I confirmed no repo path closes a
recorded tab while leaving `stopped=0` (`agent-review.sh:97` and `agent-switch.sh:96` close the
outgoing tab only after the meta already points at the replacement; `agent-spawn.sh` closes only

`stopped=1`). It is wrong that nothing here can act on it. The report frames the residual as "no
proactive reconciliation sweep exists", which sends the follow-up at writing a sweep. The actual
defect is one branch: make `harness-observe.sh` emit `runtime-agent-missing` when `agent get` fails
with `agent_not_found`, and the existing `--repair` path starts working with no sweep at all.

`harness-observe.sh` is outside this card's declared claims. The in-delta obligation is to correct
the committed claim and re-scope the follow-up; whether the one-line detector fix lands here or in a
new task is the lead's call.

### F2. The new rule cites a "relaunch flow" that refuses stopped tasks, so a premature cleanup is unrecoverable

- `agents/orchestrator.md:99-102` and `docs/herdr-runtime.md:99-101`, both new in `56e8619`.

The new text reads: `agent-review.sh`/`agent-switch.sh` "both refuse outright on a stopped task
(\"use a relaunch flow\")". No relaunch flow accepts a stopped task:

- `scripts/agent-switch.sh:24` dies on `stopped=1`. The `--relaunch` branch is at line 26, *after*
  it, so `--relaunch` cannot bypass the guard.
- `scripts/agent-review.sh:40` dies on `stopped=1`.
- `scripts/agent-spawn.sh:39-40` dies because the meta still exists: "already has runtime metadata;
  reconcile or teardown it before respawning".

Failure scenario: the lead acknowledges an engineer's `agent-done`, runs
`scripts/agent-cleanup.sh <event-id>` - the command this PR makes routine - and the meta goes to
`stopped=1`. Then `agent-review.sh <task> reviewer --brief-file <path>` returns "task agent is
stopped; use a relaunch flow"; `agent-switch.sh <task> claude --relaunch` returns the same string;
`agent-spawn.sh <task>` refuses. The only ways out are `task-teardown.sh` or hand-editing the meta.

Round 1 asked that acknowledgement "cannot block handoff". The delta answers with prose only, and
the prose names an escape hatch that does not exist. Either make the doc true (let
`agent-switch.sh --relaunch`, or `agent-review.sh`, accept `stopped=1` when the recorded tab is
already gone) or make the footgun unreachable (gate `agent-cleanup.sh` behind an explicit terminal
flag). At minimum the doc must stop asserting a recovery the code refuses.
